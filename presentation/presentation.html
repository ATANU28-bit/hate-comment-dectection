Hate Comment Detection

Project status: Production-ready inference API with fine-tuned DistilBERT — December 11, 2025

What is the project

This project detects hateful content in short text (tweets / comments). It classifies input into three labels: Hate Speech, Offensive Language, and Neither/Clean. The model is DistilBERT fine-tuned with PyTorch and exposed via a FastAPI inference server.

What we have done so far

  • Data ingestion — Loaded `data/archive/labeled_data.csv` (24,783 samples).
  • Preprocessing — Implemented advanced text cleaning: contraction expansion, emoji removal, URL & mention removal, repeated-char normalization. (See `src/preprocess_dataset.py`)
  • Class balancing — Oversampled to produce balanced dataset (19.2K per class), final splits: train 46,036 / val 5,754 / test 5,756.
  • Training — Fine-tuned DistilBERT using PyTorch (`src/train_pytorch.py`); hyperparameters: epochs=2, lr=2e-5, batch_size=16.
  • Analysis — Generated statistical reports and visualizations (`src/statistical_analysis.py`), including class distribution, token stats, and outlier detection.
  • API — Built FastAPI server (`src/api.py`) with `/health`, `/predict`, and `/predict-batch` endpoints and startup script (`scripts/run_api.py`).
  • Testing & Docs — Test suite `scripts/test_api.py`, `QUICKSTART.md`, and full API docs.

What errors we faced when API was not opening

  • Import errors — "ModuleNotFoundError: No module named 'src'" or "No module named 'inference'" when running `python src/api.py` vs `python -m uvicorn src.api:app` (Python path differences).
  • Server started then shut down — Observed Uvicorn started but application shutdown immediately. Root causes: reloader spawning child processes, permission/socket issues, or a previous process holding port 8000.
  • Socket permission error — "[WinError 10013]" from attempting to bind to the port (another process or permissions restriction).

Resolution steps taken (documented): checked process list, used `Stop-Process -Id `, restarted with `python -m uvicorn src.api:app --host 127.0.0.1 --port 8000`, fixed imports to use package-style imports, and ensured the correct working directory.
